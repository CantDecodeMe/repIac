Library: reverse proxy, API gateway y load balancer

Recorrido de las peticiones de Library por el API gateway con nginx implementado en el ejercicio 14, comparado con el despliegue anterior (un hostname por servicio). Elige una escena y usa Reproducir, o avanza paso a paso con las flechas del teclado.


    

    

      
Qué es cada cosa

      
    
        
  • Clientes: app Tkinter, Electron, navegador. Solo conocen una dirección.
    • 
        
  • Infraestructura: un solo nginx con tres funciones. Como reverse proxy oculta contenedores y puertos; como API gateway enruta /api/*, reescribe rutas, exige Bearer y limita el login; como load balancer reparte libros-ms entre dos instancias.
    • 
        
  • Microservicios de Library de ej09 más el monolito, todos por nombre de contenedor y puerto interno.
    • 
        
  • Datos: Redis (sesiones, caché, revocación) y PostgreSQL.
    • 
      

      
Basado en el ejercicio 14 desplegado sobre el ejercicio 09: los servicios no se llaman entre sí por HTTP, se coordinan por PostgreSQL y comparten Redis.
