Library: reverse proxy, API gateway y load balancer

Recorrido de las peticiones de Library con la arquitectura propuesta, comparado con la actual. Elige una escena y usa Reproducir, o avanza paso a paso con las flechas del teclado.


    

    

      
Qué es cada cosa

      
    
        
  • Clientes: app Tkinter, Electron, navegador. Solo conocen una dirección.
    • 
        
  • Infraestructura, tres piezas distintas: el reverse proxy intermedia y termina TLS; el API gateway enruta y aplica JWT, roles, cuotas y CORS; el load balancer elige una instancia sana.
    • 
        
  • Microservicios de Library (puertos de clase 5000–5005).
    • 
        
  • Datos: Redis (sesiones, caché, revocación) y PostgreSQL.
    • 
      

      
Basado en el despliegue real del ejercicio 09: los servicios no se llaman entre sí por HTTP, se coordinan por PostgreSQL y comparten Redis.
